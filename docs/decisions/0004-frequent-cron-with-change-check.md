# 0004. cron を 15 分間隔にし、変更検知でビルドを省く

## 状態

有効

## 文脈

[0001](./0001-publish-via-actions-cron.md) で公開経路を cron に一本化した時点では、
`deploy.yml` は 12 時間ごと (01:17 / 13:17 UTC) に無条件でビルド・公開していた。
Cosense で記事を書いてから公開まで最大 12 時間かかり、急ぐときは手で
`gh workflow run` する必要があった。

一方で記事の更新頻度は低く、頻度だけを上げると**ほとんどの実行が同じ内容の
再ビルド (空振り)** になる。

## 決定

- cron を **15 分ごと** (`7,22,37,52 * * * *`) にする。毎時 0 分は GitHub 全体で
  混み合い遅延・取りこぼしが出やすいので外す
- 先頭に軽い `check` ジョブを置き、**指紋が前回の公開と同じならビルドしない**。
  指紋は「UTC の日付 + main の commit SHA + Cosense の総ページ数と最終更新時刻」
  (Cosense は `/api/pages/<project>?sort=updated` を 1 回叩くだけ)
- 公開済みの指紋は actions/cache のキー (`deployed-<指紋>`) として記録し、
  `lookup-only` で有無だけを見る
- doctor で止まった指紋も記録する (内容が同じなら何度やっても止まるため)。
  それ以外の失敗は記録せず、次の起動で再試行する
- Cosense の API に届かないときは「変更あり」として扱う (従来の挙動に倒す)
- 手動実行 (`workflow_dispatch`) は判定せず常に公開する

### 却下した案

- **5 分間隔**: GitHub の schedule は最短 5 分だが、高負荷時は遅延・間引きが起きる。
  研究室サイトの記事に 5 分と 15 分の差を詰める価値は無く、起動回数が 3 倍になる
- **Cosense 側の Webhook で即時公開**: Cosense の Webhook は Slack / Discord 形式の
  通知用で、GitHub の `repository_dispatch` を直接叩けない。中継 (Cloudflare Worker 等)
  を新たに持つほどの要求ではない
- **日付を指紋に入れない (変更が無ければ何日でも公開しない)**: 稼働記録コミット
  ([0003](./0003-heartbeat-commit-keeps-cron-alive.md)) は deploy ジョブの中にあるため、
  無更新が 60 日続くとコミットが生まれず cron が止まる。指紋で拾えない変化
  (プロジェクトアイコンの差し替え等) も永久に反映されなくなる
- **`#publish` ページだけで指紋を作る**: 公開範囲の判定 (タグ・除外タグ) を
  フレームワークの外で再実装することになる。非公開ページの編集で余分に 1 回
  ビルドしても害は無いので、プロジェクト全体の最終更新時刻で十分とした

## 影響

- 記事の反映は最大 15 分 (+ GitHub の schedule 遅延) になる
- 起動回数は 1 日 2 回から 96 回に増えるが、空振りは `check` ジョブ (数秒、
  checkout も npm ci もしない) だけで終わる。リポジトリは public なので
  Actions の利用時間は課金されない
- 変更が無くても 1 日 1 回は公開まで走る (日付が変わると指紋が変わるため)
- Cosense のプロジェクト名が `cosense.config.ts` と `deploy.yml` の 2 か所に書かれる
- 公開済みの指紋は 7 日使われないとキャッシュから消えるが、消えても 1 回余分に
  公開するだけで、誤って公開を飛ばす方向には倒れない
