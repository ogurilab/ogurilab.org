# 0005. cron の間隔を 3 時間に広げる

## 状態

置換 (→ [0006](./0006-cron-every-10-minutes.md))

## 文脈

[0004](./0004-frequent-cron-with-change-check.md) で `deploy.yml` の cron を
15 分ごと (`7,22,37,52 * * * *`) にし、`check` ジョブの変更検知で空振りの
ビルドを省くようにした。

運用してみると、記事の更新頻度に対して 1 日 96 回の起動は多すぎた。起動の
ほとんどは `check` だけで終わる空振りで、Actions の実行履歴がそれで埋まり、
実際に公開した回や失敗した回を見つけにくい。研究室サイトの記事に 15 分の
即時性は求められていない。

## 決定

- cron を **3 時間ごと** (`7 */3 * * *`、UTC 00:07 / 03:07 / … / 21:07) にする。
  毎時 0 分を避けて 7 分にずらす理由は 0004 と同じ
- `check` ジョブによる変更検知・指紋の記録・手動実行の扱いは 0004 のまま変えない

### 却下した案

- **15 分のまま据え置く**: 上の文脈のとおり、起動の大半が空振りで履歴を埋める
- **1 時間ごと**: 起動は 24 回/日に減るが、反映の速さを 1 時間単位で詰める
  要求は無い。急ぐときは手動実行 (`gh workflow run "deploy website"`) がある
- **12 時間ごと (0004 以前に戻す)**: 記事を書いた日のうちに出ないことがあり、
  doctor で止まったあと Cosense 側を直しても復帰まで半日かかる

## 影響

- 記事の反映は最大 3 時間 (+ GitHub の schedule 遅延) になる。急ぐときは手動実行
- doctor で公開が止まったあと、Cosense 側を直してから自動で復帰するまでも
  最大 3 時間になる
- 起動回数は 1 日 96 回から 8 回に減る
- 1 日 1 回は必ず公開まで走る挙動 (指紋に UTC の日付を含める) は変わらないので、
  稼働記録コミット ([0003](./0003-heartbeat-commit-keeps-cron-alive.md)) による
  cron の維持にも影響しない
