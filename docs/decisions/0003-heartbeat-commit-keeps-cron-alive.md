# 0003. 稼働記録コミットでスケジュール実行を維持する

## 状態

有効

## 文脈

GitHub は**リポジトリに 60 日間アクティビティが無いとスケジュール実行を自動で
無効化する**。ワークフローが動いていること自体は活動に数えられない。

このサイトは本文を Cosense に置く ([0001](./0001-publish-via-actions-cron.md)) ため、
記事を書いてもコミットが生まれない。結果として「サイトは更新され続けているのに
リポジトリは無活動」という状態が常態化し、**実際に cron が 292 日間止まっていた**。
その間、記事を書いても公開されなかった。

止まった後の復旧も素直ではない。`gh workflow enable "deploy website"` は**名前解決に
失敗して黙って何もしない** (`state` は `active` を返すのに実体は無効のままで、dispatch
してもジョブが 0 件のまま滞留する)。ID 指定でしか有効化できない。

## 決定

`deploy.yml` が**月に一度だけ** `.github/last-deploy.json` を更新してコミットし、
リポジトリを活動状態に保つ。ログに現れる `chore: 稼働記録を更新する (YYYY-MM)` が
これにあたる。

## 影響

- **main へ github-actions[bot] が直接コミットする経路が常設される**。この経路は
  署名されず、PR も経由しない。リポジトリ側のマージ保護を設計するときは、
  PR 必須ルールと署名必須ルールがこの経路を黙って止めることに注意する
  (止まれば 292 日停止の再来になる)
- コミットは fast-forward な push なので、直線履歴の要求とは矛盾しない
- `.github/last-deploy.json` は自動生成物。手で消したり内容を当てにしたりしない
- 万一止まったときは ID 指定で有効化する:

  ```bash
  gh api -X PUT repos/ogurilab/ogurilab.org/actions/workflows/99228705/enable
  ```
